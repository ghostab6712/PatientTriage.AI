# PatientTriage.AI

An AI-assisted emergency triage prototype that combines machine-learning predictions with a rule-based clinical risk engine and a human-in-the-loop review workflow.

> **Prototype / educational project:** This system uses synthetic patient data and is not clinically validated. It must not be used for real-world medical decision-making.

## Overview

PatientTriage.AI is designed to demonstrate how an emergency-department triage workflow can combine:

- Patient vital signs and clinical information
- Machine-learning risk classification
- Rule-based clinical risk scoring
- AI confidence and safety escalation
- Explainability for risk decisions
- Human clinical review and nurse decisions
- Reassessment and assessment history
- Emergency-department surge simulation

The project focuses on making an AI recommendation **reviewable and actionable**, rather than treating the model as an autonomous decision-maker.

## Key Features

### AI Triage

The system classifies patients into four risk categories:

- `LOW`
- `MODERATE`
- `HIGH`
- `CRITICAL`

Each assessment also produces a priority level (`P1`–`P4`), a recommended pathway, and a reassessment interval.

### Machine Learning

The backend contains a trained triage model:

```text
Backend/
└── models/
    └── triage_model.pkl
```

Training is performed with the synthetic dataset generated by:

```text
Backend/data/generate_data.py
```

The current prototype dataset contains 10,000 synthetic patient records.

### Rule-Based Risk Engine

The project also contains a deterministic risk engine:

```text
Backend/app/risk_engine.py
```

It evaluates clinical factors including:

- Oxygen saturation
- Systolic blood pressure
- Heart rate
- Respiratory rate
- Pain score
- Age
- Consciousness
- Chief complaint

The engine produces a capped risk score from 0–100 and a list of reasons explaining which risk factors contributed to the score.

### AI Confidence & Safety

The application exposes the ML model's confidence based on its class probabilities.

The frontend uses prototype safety thresholds:

```text
< 60%      → HUMAN CLINICAL REVIEW REQUIRED
60–69%     → CAUTION — CLINICAL REVIEW RECOMMENDED
≥ 70%      → HIGHER AI CONFIDENCE
```

These thresholds are demonstration safeguards and are **not clinically validated thresholds**.

### Explainability

The patient assessment displays:

- Risk level
- Priority
- Risk score
- Clinical reasons generated by the existing risk engine

Example:

```text
Why This Assessment?

✓ Very low oxygen saturation
✓ Low systolic blood pressure
✓ Very high heart rate
✓ Elevated respiratory rate
✓ Severe pain
✓ Older age increases risk
✓ Chest-related complaint

Risk Score: 100/100
```

### Human-in-the-Loop Review

A nurse/clinician can:

- Accept the AI recommendation
- Modify the recommendation
- Override the recommendation

Override decisions require a reason, and decisions are stored in the assessment history.

### Missing-Data Safety

Reassessment does not silently substitute an old value when a required field is intentionally cleared.

If required clinical information is unavailable:

```text
Missing data
    ↓
HUMAN REVIEW REQUIRED
    ↓
Automated reassessment blocked
    ↓
No new assessment created
```

This was tested with a missing SpO₂ value.

### Reassessment

Patients can be reassessed with updated clinical measurements.

A valid reassessment creates a new assessment while preserving previous assessments in the history.

### Emergency Department Surge Simulation

The dashboard includes a 3× emergency-department surge simulation.

The simulation demonstrates increased workload while explicitly keeping simulated arrivals separate from the real patient database.

It does not create fake patients in the production patient records.

## Model Training

The model can be trained using:

```powershell
cd Backend
.env\Scripts\Activate.ps1
python train_model.py
```

The trained model is saved under:

```text
Backend/models/triage_model.pkl
```

The current prototype training/evaluation run reported approximately **99.6% accuracy** on the synthetic dataset.

### Important Model Limitation

The synthetic labels are generated from predefined rules using clinical variables that are also available to the ML model. Therefore, the high validation accuracy demonstrates that the prototype learned the synthetic labeling pattern; it does **not** demonstrate equivalent performance on real clinical patients.

Real-world deployment would require appropriately collected clinical data, external validation, calibration, bias evaluation, clinical validation, monitoring, governance, and regulatory review.

## Example Workflow

```text

        ↓

        ↓

        ↓
4. Review risk + confidence
        ↓

        ↓

        ↓

        ↓
8. Store clinical decision
        ↓
9. Reassess when required
        ↓
10. Review assessment history
```

## Safety Design

The prototype deliberately keeps the human reviewer in the decision loop.

Important safeguards demonstrated by the application include:

- Confidence-based review escalation
- Missing-data blocking during reassessment
- Explicit explainability
- Nurse acceptance/modification/override
- Stored decision history
- Reassessment scheduling
- Separation of surge simulation from real patient records

The application should be considered an **AI-assisted prototype**, not an autonomous clinical system.

## Limitations

This project has several important limitations:

1. The patient dataset is synthetic.
2. The model has not been clinically validated.
3. Reported model accuracy is only meaningful within the synthetic data generation setup.
4. Prototype confidence thresholds are not clinically validated.
5. Risk-engine rules are simplified demonstrations and are not a substitute for clinical protocols.
6. The application is intended for demonstration and educational purposes.
7. Production deployment would require substantially stronger security, privacy, reliability, validation, monitoring, and governance.

## Interview Talking Points

A key design principle of PatientTriage.AI is:

> **The AI recommends; the clinician remains responsible for the final decision.**

The project combines two complementary approaches:

```text
Machine Learning
→ learns a triage classification pattern

Rule-Based Risk Engine
→ provides deterministic clinical risk factors
  and human-readable reasons
```

This allows the system to demonstrate both predictive modeling and transparent decision support while retaining human oversight.
